# Pixora code wiki quickstart

Pixora is a React/Vite image and presentation creation application with a Node BFF API, PostgreSQL tenant data and sessions, Azure Blob assets, Gemini/Azure AI providers, and optional LINE bot sharing. This wiki is the generated, code-derived record of current browser, server, data, and operational behavior; source remains authoritative. Keep external portal setup, deployment-secret placement, product vision, audits, and unimplemented proposals in `docs/` rather than duplicating current implementation guidance there. Start with [architecture](architecture/overview.md), then use the router below.

The BFF session, tenant identity, API routes, AI jobs, and resource ownership are cross-system concerns summarized in [architecture](architecture/overview.md). Browser-side provider token and direct GPT Image clients are not current runtime surfaces.

## Main concepts

- **Browser runtime:** [browser application and authentication](frontend/application.md) owns React startup, routes, login presentation, authenticated shell composition, UI session state, and credentialed API requests; it bootstraps from [server sessions](backend/sessions.md). [Shared UI motion, theme, mobile browser baseline, and semantic icons](frontend/design-system.md) supplies the synchronized theme/status-bar decision, mobile viewport/safe-area/touch baseline, structural media query, stacked history-layer lifecycle, lazy Motion reduced-motion boundary, login shader fallback, semantic glyphs, and shared Tailwind primitive styling used by browser features. [Administrator panel and history preview](frontend/admin-panel.md) is the separately routed, role-gated management UI and uses the shared image modal without changing management API ownership.
- **BFF authentication and tenant policy:** [server sessions](backend/sessions.md) exchanges provider identity for opaque cookies and protects unsafe API requests with CSRF; [authentication and administration](backend/auth-tenancy-admin.md) resolves it to persisted tenant access, records the active sign-in provider for administration, and owns image policy plus encrypted analysis-model assignments that [AI generation](backend/ai-generation.md) consumes.
- **Creation experience:** [creation workflows](frontend/create-workflows.md) owns the unified create form and result preview. On phones, it replaces the inline preview with a compact generation bar, a bottom-sheet output editor, and a full-screen result that shares layered back/Escape behavior with the expanded canvas; desktop and tablet keep inline settings and preview composition. Optional attachments route by purpose to content-reference generation or refine/background/element/style edits, while the preview can refine its selected in-memory version, branch from older versions, and expand into direct-parent hold or slider comparison. Near-duplicate prompt guidance opens the phone result when needed and focuses the visible refine input without blocking regeneration. A separate collapsible advanced-style section owns reusable styles and style-reference analysis. The workflow also owns GPT Image quality, in-image text preferences, prompt coaching, shared job polling, storyboard editing, browser exports, and the PPT Master studio; [Asset Center](frontend/asset-center.md) separately owns template, saved-style, and generation-history management.
- **AI and deck workers:** [AI generation](backend/ai-generation.md) owns provider calls, prose prompt/scene optimization, reusable style analysis, document storyboard analysis, and GPT image jobs. [PPT Master deck jobs](backend/ppt-master-decks.md) is a separate tenant-scoped, asynchronous SVG-to-native-PPTX workflow that stores finished decks in Blob Storage, records a durable stage/slide timeline and replaceable per-page SVG previews, and uses the Python sidecar; [creation workflows](frontend/create-workflows.md) owns the browser preview cache and rail.
- **Assets and persistence:** [owner-scoped uploads](backend/uploads.md) owns the authenticated create-PUT-complete lifecycle, fixed staging/ready Blob names, input-consumer access checks, and expiry cleanup; it supplies ready IDs to [AI generation](backend/ai-generation.md) and deck jobs. [resources](backend/resources.md) owns history attribution, styles/templates, Azure Foundry query/document embeddings, generated assets, and LINE. [schema](data/schema.md) is canonical for durable constraints, including uploads, the 1536-dimensional style vector, document-analysis jobs, nullable legacy history source, auth-provider attribution, deck jobs and their append-only events, and migration order.
- **Operations:** [development, migrations, and deployment](operations/development-deployment.md) covers local commands, BFF configuration, upload cleanup/lifecycle rollout, deployment boundaries, Entra callback constraints, and the separately deployed PPT Master sidecar.

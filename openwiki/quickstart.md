# Pixora code wiki quickstart

Pixora is a React/Vite image and presentation creation application with a Node BFF API, PostgreSQL tenant data and sessions, Azure Blob assets, Gemini/Azure AI providers, and optional LINE bot sharing. This wiki explains browser, server, data, and operational ownership boundaries—not a replacement for source or provider setup guides. Start with [architecture](architecture/overview.md), then use the router below.

The BFF session, tenant identity, API routes, AI jobs, and resource ownership are cross-system concerns summarized in [architecture](architecture/overview.md). Browser-side provider token and direct GPT Image clients are not current runtime surfaces.

## Main concepts

- **Browser runtime:** [browser application and authentication](frontend/application.md) owns React startup, routes, UI session state, and credentialed API requests; it bootstraps from [server sessions](backend/sessions.md). [Administrator panel and history preview](frontend/admin-panel.md) is the separately routed, role-gated management UI and uses the shared image modal without changing management API ownership.
- **BFF authentication and tenant policy:** [server sessions](backend/sessions.md) exchanges provider identity for opaque cookies and protects unsafe API requests with CSRF; [authentication and administration](backend/auth-tenancy-admin.md) resolves it to persisted tenant access, image policy, and encrypted analysis-model assignments that [AI generation](backend/ai-generation.md) consumes.
- **Creation experience:** [creation workflows](frontend/create-workflows.md) owns storyboard editing, transforms, browser-produced exports, editable company-template presentation slides, and the PPT Master browser studio; [Asset Center](frontend/asset-center.md) separately owns template, saved-style, and generation-history management.
- **AI and deck workers:** [AI generation](backend/ai-generation.md) owns provider calls, server rendering, and GPT image jobs. [PPT Master deck jobs](backend/ppt-master-decks.md) is a separate tenant-scoped, asynchronous SVG-to-native-PPTX workflow that stores finished decks in Blob Storage, records a durable stage/slide timeline and replaceable per-page SVG previews, and uses the Python sidecar; [creation workflows](frontend/create-workflows.md) owns the browser preview cache and rail.
- **Assets and persistence:** [resources](backend/resources.md) distinguishes direct SAS upload from generated-job Blob output; [schema](data/schema.md) is canonical for durable constraints, including deck jobs and their append-only events, and migration order.
- **Operations:** [development, migrations, and deployment](operations/development-deployment.md) covers local commands, BFF configuration, deployment boundaries, Entra callback constraints, and the separately deployed PPT Master sidecar.

## Backlog / evidence limitations

- No dedicated API handler tests were found for tenant analysis-model management/role resolution, document-analysis normalization, company-template PPTX validation/headers, GPT image jobs, PPT Master deck jobs or their event trace/slide previews, resource APIs, LINE, or migrations. `deckContract.test.js` covers local outline/SVG constraints; `deckPreview.test.js` covers recognized-image inlining and path refusal; `usePptMasterDeck.test.jsx` and `aiService.test.js` cover mocked client resumption, polling, preview revision cache, and URL release; `deckSteps.test.js`, `DeckTimeline.test.jsx`, `DeckSlideRail.test.jsx`, and `PptMasterStudio.test.jsx` cover client reduction/rendering, rail selection, and preview composition. There is still no focused PPT Master catalog-handler, worker, tenant/download/preview, event/preview-serialization, or migration test. No focused `PresentationGenerator` component test covers editing, slide deletion/re-numbering, or download errors; existing schema, renderer, and frontend service/unit tests cover selected contracts only.
- `AssetCenter` has no focused component test, and `api/templates/index.js` replacement-style PUT is not covered by an adapter or handler test. `AssetMetadataSheet.test.jsx` covers style optimization only; it does not cover metadata save failures or template-field preservation. `AssetViewModeToggle.test.jsx` covers only the toggle control, not URL synchronization. `StyleCard.test.jsx` covers preview emission and `ImageLightbox.test.jsx` covers Escape plus optional controls/navigation, but neither covers focus restoration or backdrop close. The Asset Center currently retains template replacement fields in its metadata-edit payload; add coverage for that preservation contract; see [Asset Center](frontend/asset-center.md) and [resources](backend/resources.md).
- `AdminHistoryPreview.test.jsx` covers the mocked browser workflow, but there is no focused `api/admin/index.js` handler test for management history pagination, tenant scope, authorization, or response mapping. Add server tests before changing that contract; see [administrator panel](frontend/admin-panel.md) and [authentication and administration](backend/auth-tenancy-admin.md).
- LIFF is present as a dependency/configuration concept but has no source consumer or fallback runtime path; LINE sharing currently requires a configured bot binding.

Use `pnpm lint && pnpm test && pnpm build` as the compact frontend baseline only when broad frontend validation is warranted. Follow [development, migrations, and deployment](operations/development-deployment.md) for API and migration work.

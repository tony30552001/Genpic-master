# Pixora code wiki quickstart

Pixora is a React/Vite image and presentation creation application with a Node BFF API, PostgreSQL tenant data and sessions, Azure Blob assets, Gemini/Azure AI providers, and optional LINE bot sharing. This wiki is the generated, code-derived record of current browser, server, data, and operational behavior; source remains authoritative. Keep external portal setup, deployment-secret placement, product vision, audits, and unimplemented proposals in `docs/` rather than duplicating current implementation guidance there. Start with [architecture](architecture/overview.md), then use the router below.

The BFF session, tenant identity, API routes, AI jobs, and resource ownership are cross-system concerns summarized in [architecture](architecture/overview.md). Browser-side provider token and direct GPT Image clients are not current runtime surfaces.

## Main concepts

- **Browser runtime:** [browser application and authentication](frontend/application.md) owns React startup, routes, UI session state, and credentialed API requests; it bootstraps from [server sessions](backend/sessions.md). [Administrator panel and history preview](frontend/admin-panel.md) is the separately routed, role-gated management UI and uses the shared image modal without changing management API ownership.
- **BFF authentication and tenant policy:** [server sessions](backend/sessions.md) exchanges provider identity for opaque cookies and protects unsafe API requests with CSRF; [authentication and administration](backend/auth-tenancy-admin.md) resolves it to persisted tenant access, records the active sign-in provider for administration, and owns image policy plus encrypted analysis-model assignments that [AI generation](backend/ai-generation.md) consumes.
- **Creation experience:** [creation workflows](frontend/create-workflows.md) owns GPT Image quality and general image-purpose selection, the persisted in-image-text preference and its general/storyboard optimizer propagation, storyboard editing, transforms, browser-produced exports, and the PPT Master browser studio; [Asset Center](frontend/asset-center.md) separately owns template, saved-style, and generation-history management.
- **AI and deck workers:** [AI generation](backend/ai-generation.md) owns provider calls, prose prompt/scene optimization, reusable style analysis, document storyboard analysis, and GPT image jobs. [PPT Master deck jobs](backend/ppt-master-decks.md) is a separate tenant-scoped, asynchronous SVG-to-native-PPTX workflow that stores finished decks in Blob Storage, records a durable stage/slide timeline and replaceable per-page SVG previews, and uses the Python sidecar; [creation workflows](frontend/create-workflows.md) owns the browser preview cache and rail.
- **Assets and persistence:** [owner-scoped uploads](backend/uploads.md) owns the authenticated create-PUT-complete lifecycle, fixed staging/ready Blob names, input-consumer access checks, and expiry cleanup; it supplies ready IDs to [AI generation](backend/ai-generation.md) and deck jobs. [resources](backend/resources.md) owns history attribution, styles/templates, generated assets, and LINE. [schema](data/schema.md) is canonical for durable constraints, including uploads, document-analysis jobs, nullable legacy history source, auth-provider attribution, deck jobs and their append-only events, and migration order.
- **Operations:** [development, migrations, and deployment](operations/development-deployment.md) covers local commands, BFF configuration, upload cleanup/lifecycle rollout, deployment boundaries, Entra callback constraints, and the separately deployed PPT Master sidecar.

## Backlog / evidence limitations

- No dedicated API handler tests were found for tenant analysis-model management/role resolution, GPT image jobs, PPT Master deck jobs or their event trace/slide previews, resource APIs other than LINE/upload consumers, or migrations. `document-analysis-jobs/__tests__/index.test.js` covers owner-scoped job creation/status; `documentAnalysisJobs.test.js` covers queue claiming and result persistence; `analyze-document/__tests__/index.test.js` covers owned upload/base64 validation and response mapping. These do not prove a live worker/database/Blob integration or migration deployment. `deckContract.test.js` covers local outline/SVG constraints plus image-density selection; `deckImages.test.js` and `imageProviders.test.js` cover prompt/credential/provider helpers; `deckPreview.test.js` covers recognized-image inlining and path refusal; `usePptMasterDeck.test.jsx` and `aiService.test.js` cover mocked client resumption, polling, preview revision cache, and URL release; `deckSteps.test.js`, `DeckTimeline.test.jsx`, `DeckSlideRail.test.jsx`, and `PptMasterStudio.test.jsx` cover client reduction/rendering, rail selection, and preview composition. There is still no focused PPT Master catalog-handler, worker, tenant/download/preview, or event/preview-serialization test, and no migration integration test (although `deckEventSteps.test.js` checks the event-step constraint source).
- `api/_shared/__tests__/imageTextLanguage.test.js` verifies a recognized optimizer mapping, quoted-text/default-language generation wording, generation `none`, and missing/unsupported values; `imagePrompt.test.js` verifies that freeform adds no system directive and that other purposes defer to author-specified framing. There is no focused test that `ScriptEditor` renders/forwards the image-purpose selector or that `ScriptEditor` or `DocumentScenes` forwards `imageLanguage`, that `aiService` serializes either optimizer request, or that `/optimize-prompt` and `/optimize-scene` pass the directive to the assigned model. There is also no focused handler test for reusable `style_prompt` subject independence or image-transform mode wording; see [AI generation](backend/ai-generation.md) and [creation workflows](frontend/create-workflows.md).
- `AssetCenter` has no focused component test, and `api/templates/index.js` replacement-style PUT is not covered by an adapter or handler test. `AssetMetadataSheet.test.jsx` covers style optimization only; it does not cover metadata save failures or template-field preservation. `AssetViewModeToggle.test.jsx` covers only the toggle control, not URL synchronization. `StyleCard.test.jsx` covers preview emission and `ImageLightbox.test.jsx` covers Escape plus optional controls/navigation, but neither covers focus restoration or backdrop close. The Asset Center currently retains template replacement fields in its metadata-edit payload; add coverage for that preservation contract; see [Asset Center](frontend/asset-center.md) and [resources](backend/resources.md).
- `api/admin/__tests__/adminResources.test.js` covers URL-free history list mapping, tenant-scoped history/style image lookup, a missing asset, the image cache header, literal-safe user search, provider fields in user/options responses, recognized/legacy history-source filters, and unsupported-source rejection; `AdminPanelSectionLoading.test.jsx` covers lazy section loading, active-section-only filter refresh, provider-separated selector search, debounced user search forwarding, and source-filter request forwarding. It does not cover management list pagination, `userId` filters, admin authorization, user role/status mutations, style deletion, browser search pagination retention, or the ordinary history POST source-normalization handler. Add those server/consumer checks before changing those contracts; see [administrator panel](frontend/admin-panel.md), [resources](backend/resources.md), and [authentication and administration](backend/auth-tenancy-admin.md).
- `023_deck_event_design_step.sql` now widens `deck_job_events.step` to include the worker's `design` stage, and `deckEventSteps.test.js` compares the final migration constraint against `DECK_STEPS`. There is still no focused event/handler serialization test: add one before changing the event response contract; see `api/_shared/deckJobs.js`, `api/deck-jobs/index.js`, and `db/migrations/023_deck_event_design_step.sql`.
- LIFF is present as a dependency/configuration concept but has no source consumer or fallback runtime path; LINE sharing currently requires a configured bot binding.

Use `pnpm lint && pnpm test && pnpm build` as the compact frontend baseline only when broad frontend validation is warranted. Follow [development, migrations, and deployment](operations/development-deployment.md) for API and migration work.

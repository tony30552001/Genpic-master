# Browser application and authentication

`src/main.jsx` is the browser composition root: it mounts `GoogleOAuthProvider`, `AuthProvider`, `MotionProvider`, and `App`. `MotionProvider` supplies the lazy animation runtime and user reduced-motion preference; the header inside `InfographicGenerator` exposes `ThemeToggle`. Their styling/runtime boundary is canonical in [shared UI motion, theme, and semantic icon styling](design-system.md). It no longer initializes MSAL or handles a browser-side provider redirect. Microsoft sign-in is a full-page navigation to the BFF; Google supplies a credential to the BFF once. The server-side flow, cookies, and authorization-code exchange are canonical in [server sessions and BFF sign-in](../backend/sessions.md).

## Routing

`App` exposes public `/login` and protected `/`, `/library`, and `/admin` routes. `ProtectedRoute` waits for `useAuth` initialization and redirects an unauthenticated location to `/login`. `ProtectedAdminRoute` shows its loading status exactly when `isLoading || (isAuthenticated && !profile && !profileError)`. It does not read `isProfileLoading`: an authenticated initial request remains gated in the timer gap before that flag becomes true, while an initial profile error stops the spinner and, without an admin profile, redirects to `/`. Consequently, initial authorization cannot briefly expose the admin page, while an explicit `refreshProfile` for an already authorized admin leaves the mounted children in place. A refresh that returns a non-admin role redirects to `/` after it completes. The management workspace and its retained local state are described in [administrator panel and history preview](admin-panel.md). `LibraryPage` reads `section` and `view` from the query string and passes them as initial library inputs to `InfographicGenerator`. `AssetCenter` owns the current query state: `section` accepts `overview`, `templates`, `styles`, or `history` and falls back to `overview`; `view` accepts `grid`, `list`, or `table` and falls back to `table`. The library's browser composition and resource callbacks are specified in [Asset Center](asset-center.md).

## Browser session lifecycle

At mount, `AuthProvider` clears legacy `google_user` and `msal.*` local-storage values, then calls `getAuthSession`. That function makes unauthenticated `GET /api/auth/session`; when the response is authenticated it keeps the returned user in React state and saves the returned CSRF value only in the module-local `apiClient` variable. A no-session response clears both user/profile state and the CSRF value.

`loginWithMicrosoft` navigates to `/api/auth/entra/start` with a URL-encoded `returnTo`. The login page preserves the protected route's pathname, query, and hash in that value; the auth service normalizes a direct `/login` invocation to `/`. The API creates and validates Entra state, receives the callback, and returns to that path with the HttpOnly session cookie. `loginWithGoogle` sends `{ credential }` once to `/api/auth/google`, then reloads session state. Neither provider credential is persisted by this code.

`AuthProvider` loads `/api/me` after a server session establishes `user`. The `GET /api/me` response is top-level `{ user, modelPolicy, imageModels }`; `AuthContext` deliberately spreads `data.user` into its `profile` and adds `modelPolicy` plus normalized `imageModels`, so consumers read `profile.role`, `profile.modelPolicy`, and `profile.imageModels` rather than `profile.user`. `profile.role` derives `isAdmin`. All protected routes wait for session initialization; the admin route uses the exact `isLoading || (isAuthenticated && !profile && !profileError)` guard from the routing section, rather than `isProfileLoading`. `refreshProfile` is explicit: a failed refresh retains the current profile and admin authorization, sets `profileError`, and rejects to its caller. This keeps mounted administration state and save/refresh-failed notifications intact; generation remains blocked by `isProfileLoading` or `profileError` until a successful retry replaces the profile. A session initialization or identity change clears the old profile before loading the new one, so prior authorization is never reused for a different session. `handleLogout` calls the CSRF-protected API logout and clears local state even if that request fails. `SessionExpiryBanner` and `LoginPage` expose both sign-in choices when `apiClient` reports expiry.

## Login presentation

`LoginPage` is presentation and recovery UI; it does not own a second authentication flow. It redirects an already authenticated visitor to the protected route recorded in router state—including pathname, query, and hash—or `/`. It passes that same return target to the Microsoft BFF navigation, renders `LoginLoadingState` while `useAuth` bootstraps the BFF session, and delegates Google success to `handleGoogleLoginSuccess`. A Google-widget failure is page-local state; it is displayed alongside `profileError` or session expiry, without changing the server session contract.

`ResponsiveGoogleLogin` measures its container with `ResizeObserver` and constrains the provider widget width to 200–400 pixels. Its Google control uses the outline theme even if the application root is dark. The page deliberately applies `login-light-theme`, so the sign-in panel remains a light, provider-neutral surface rather than inheriting the authenticated application's theme. `LoginShaderBackground` belongs to the shared styling/motion boundary in [shared UI motion, theme, and semantic icon styling](design-system.md): it is decorative, dynamic-loads its shader implementation only after a WebGL2 check, and is static for reduced-motion users or incompatible browsers.

## API client contract

`apiClient` uses `fetch` with `credentials: "include"` for all requests. `buildHeaders` adds JSON content type as needed and adds `X-CSRF-Token` only for unsafe methods (`POST`, `PUT`, `DELETE`, and other non-safe methods), unless `auth: false` or `csrf: false` is explicit. If an unsafe request lacks an in-memory CSRF value, it fails locally with `AuthExpiredError` before it reaches the network.

A protected 401 notifies the handler registered by `AuthProvider`, which clears state and shows an expiry warning; there is no token-refresh retry. Abort errors still propagate unchanged. The API verifies the cookie and CSRF header independently; this client behavior is a usability guard, not the security control. See [server sessions](../backend/sessions.md) for middleware ordering and [HTTP API](../backend/http-api.md) for endpoint registration.

## Change and validation guide

Consult this page for sign-in buttons, browser-root provider order, protected-route state, profile refresh, client request credentials, CSRF headers, or expiry UX. For `/admin`, preserve the exact loading guard `isLoading || (isAuthenticated && !profile && !profileError)`: it deliberately covers the initial profile timer gap, stops on an initial profile error without granting access, and does not read `isProfileLoading`. Consult [shared UI motion, theme, and semantic icon styling](design-system.md) instead for the `MotionProvider` implementation, theme pre-paint/runtime synchronization, login shader, animation package, or icon policy. Follow the complete seam: `src/App.jsx` owns route loading and redirects; `src/context/AuthContext.jsx` owns session/profile state and `refreshProfile`; `src/services/authService.js` owns auth endpoint calls and BFF navigation; `src/services/adminService.js` owns the `/api/me` request; `src/services/apiClient.js` owns credential and CSRF request behavior; and `src/components/auth/SessionExpiryBanner.jsx` / `src/pages/LoginPage.jsx` render recovery UI. For a route-refresh change, preserve the distinction between initial/identity-changing authorization (no stale profile) and explicit refresh of an already authorized profile (children stay mounted), then run `src/__tests__/App.test.jsx`. For a login-UI change, keep the existing callbacks and redirect semantics, preserve the loading status and local Google error, and change `LoginShaderBackground.jsx` / `src/index.css` with the page only when its visual capability or fallback contract changes. Server behavior belongs in [server sessions](../backend/sessions.md), not a new browser token implementation.

Keep the client’s in-memory CSRF rule aligned with the API’s unsafe-method enforcement. Do not restore `X-Auth-Token`, browser MSAL initialization, provider-token storage, or a direct-GPT credential path: those modules were removed in favor of server-owned sessions and generation.

Run the focused browser checks:

```sh
pnpm test --run src/__tests__/App.test.jsx src/context/__tests__/AuthContext.test.jsx
```

`App.test.jsx` is the route-composition suite: with the real `AuthProvider` and `App` but mocked pages/services, it verifies four cases—initial authorization waits before a resolved viewer is denied; successful refresh retains mounted admin state and its saved notification; failed refresh retains mounted state and reports the failure; and role revocation redirects. The initial-profile-error stop-and-deny behavior is specified directly by the `ProtectedAdminRoute` condition in `App.jsx`. `LoginPage.test.jsx` is the focused presentation suite: it covers both provider callbacks, light-page isolation under a dark root, Google failure display, auth error precedence, loading status, and return-route redirect. `AuthContext.test.jsx` covers BFF-session bootstrap/profile loading, public `imageModels` and `modelPolicy`, unconfigured admin access, refresh replacement, refresh failure that preserves authenticated admin state and sets `profileError`, rejected refresh calls, and retry. The auth-service suite covers session load/CSRF storage, Google posting, BFF Microsoft redirect, and logout clearing. The API-client suite covers cookie credentials, CSRF inclusion/missing-token rejection, 401 notification, and 204 handling. Perform an interactive browser check only when changing the login UI, `VITE_API_BASE_URL`, or return routing; it must cover a post-login session bootstrap, a mutation after CSRF bootstrap, logout, and expired-session recovery. Use [operations](../operations/development-deployment.md) for callback and CORS setup.

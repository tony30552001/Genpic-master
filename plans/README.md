## Shared facts every executor needs

- **Package manager**: the frontend uses the repo-pinned pnpm —
  `corepack pnpm …`, never bare `npm`.
- **`LazyMotion` is in `strict` mode** at
  `src/components/motion/MotionProvider.jsx:9`. `motion.div` throws. Import
  elements from `motion/react-m` (`import * as M from "motion/react-m";`);
  `AnimatePresence` comes from `motion/react`.
- **Reduced motion is handled by the provider.**
  `<MotionConfig reducedMotion="user">` strips transform values (`scale`, `x`,
  `y`, `rotate`) and layout projection while keeping `opacity`. Do not add
  `motion-reduce:*` classes or `useReducedMotion()` branches to `motion`-driven
  elements. CSS-driven animation still needs `motion-reduce:animate-none`.
- **Motion tokens**:
  - `src/index.css` — `--motion-enter: 250ms`, `--motion-exit: 150ms`,
    `--motion-hover: 200ms` (all collapse to `0.01ms` under
    `prefers-reduced-motion`); `--ease-emphasized: cubic-bezier(0.22, 1, 0.36, 1)`,
    `--ease-exit: cubic-bezier(0.4, 0, 0.2, 1)`.
  - `tokens.css` — `--dur-micro: 120ms`, `--dur-short: 180ms`, `--dur-long: 300ms`,
    `--ease-out: cubic-bezier(0.16, 1, 0.3, 1)`. **`--dur-*` are NOT collapsed by
    the reduced-motion block** — anything using them must handle it explicitly.
  - `src/lib/motionTokens.js` — `GLYPH_SPRING`, `GLYPH_FEEDBACK` (0.16s),
    `GLYPH_SUCCESS` (0.32s), `GENERATION_LOOP` (1.8s loop).
- **Validation** (run the narrowest that covers the change):
  ```powershell
  corepack pnpm lint
  corepack pnpm exec vitest run <test-file>
  corepack pnpm build
  ```

## What was deliberately NOT planned

Recorded so nobody re-opens these:

- **Desktop tab bar** (`src/InfographicGenerator.jsx:699-714`) and **mobile
  bottom navigation** (`:1221-1305`), including a `layoutId` sliding active
  indicator. Highest-frequency controls in the product — animation makes them
  feel slower. They are correct as-is.
- **Top-level tab panel swaps** (`:849`, `:1049`, `:1096`, `:1138`). Viewport-sized
  panels; a crossfade would read as lag.
- **Hold-to-confirm on destructive actions** (`AdminPanel.jsx:533`, `:603`,
  `ImageModelSettings.jsx:99`). Already gated by an explicit confirmation step;
  adding a 2s hold is pure friction.
- **Progress bars and `DeckTimeline`**. Functional data the user is reading;
  already transition correctly.
- **Empty-state entrances** (`HistoryPanel.jsx:466`). A dead-end the user wants to
  leave — motion only delays the CTA.
- **`duration-500` image reveals** (`ImagePreview.jsx:95`, `:126`,
  `ImageTransformPanel.jsx:106`). Over the 300ms UI budget on purpose: the payoff
  after a multi-second generation is where a longer beat is earned.
- **`ImageGeneratingState` ambient loop, `HistoryCard` hover scale,
  `AssetCenter` card stagger.** Already implemented correctly, including
  reduced-motion handling.

## Non-motion observations found while planning

Out of scope for these plans; recorded for whoever owns them:

1. **Duplicated `ImageLightbox`.** `src/components/create/DocumentScenes.jsx:148`
   defines a private `ImageLightbox` and never imports the shared
   `src/components/common/ImageLightbox.jsx`. Plan 003 therefore has to apply the
   same exit treatment twice. Consolidating them is a structural refactor with
   its own test surface.
2. **Missing `role="alert"`.** The generation error and warning banners at
   `src/InfographicGenerator.jsx:856` and `:862` are plain `div`s, so screen
   readers are not notified. The sibling `profileError` banner at `:840` does
   have `role="alert"`. Plan 006 explicitly does not fix this — it is an
   accessibility change, not a motion change.
3. **Native `window.confirm` for destructive actions.** `AdminPanel.jsx:533`,
   `:603`, `ImageModelSettings.jsx:99`, and `LineSettings.jsx:109` use browser
   confirms while `HistoryPanel.jsx:525` uses the `AlertDialog` primitive. A
   consistency issue, not an animation one.
